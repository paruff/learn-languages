# Spec — Acquira (learn-languages)

> **What this file is:** the living, testable contract for _what the product does_. Each requirement has an ID, traces to `intent.md`, and names the check that proves it.
> **Update it in the same PR as any behaviour change.** If code and spec disagree, that's a bug in one of them, and the PR must say which.
>
> Deep design detail (schemas, SM-2 maths, budgets) lives in `specification-design.md`, and the UI/UX design system in `DESIGN.md`. This file stays at the requirement level and links into them instead of copying them.
> Per-feature design notes go in `plans/YYYY-MM-DD-<topic>.md` and must cite the requirement IDs they add or change here.

**Intent column:** `P#` principle, `SIG#` success signal, or `§n` section of `intent.md`. Spec IDs S1–S11 are learner-state requirements; intent signals are always written `SIG#`.

**Spec version:** 1.6 (2026-11-09) · **Status legend:** ✅ shipped and verified · 🟡 partial · ⬜ not started

**Terms.** _Item_: one vocabulary entry in one language. _Card_: an item shown in review in one direction (forward or reverse). _Word_: the learner-facing name for an item. _Realisation_: one language's content for a CEFR node. _Round-robin_: taking one card from each node in turn. _JTBD_: jobs to be done (`discovery-brief.md`).

### 2.1 Scheduling transitions (current SM-2)

UI grade → SM-2 quality is `gradeToQuality` in `src/utils/srs.ts`. Intervals use the ease before the update.

| Grade (quality) | Counts as | Repetitions | Interval                   | Ease change |
| --------------- | --------- | ----------- | -------------------------- | ----------- |
| Again (1)       | lapse     | reset to 0  | 1 day                      | none        |
| Hard (3)        | pass      | +1          | 1, 6, then interval × ease | −0.14       |
| Good (4)        | pass      | +1          | as Hard                    | none        |
| Easy (5)        | pass      | +1          | as Hard                    | +0.10       |

- Ease starts at 2.5 and never drops below 1.3. A lapse does not lower ease, and there is no leech handling: a card that keeps failing restarts at 1 day each time (known limit).
- Due rule: `dueDate` is the ISO instant of 00:00 local time, `interval` days after the grade day. A card graded at 9pm with a 1-day interval is due from midnight, so it is there the next morning. The review queue is built once when a session starts, so a session that runs past midnight does not re-offer cards graded in it. Travel across time zones shifts the due instant by the offset; that is accepted.
- Mastery (L9) needs interval ≥ 21 days: four passes in a row (1, 6, 15, 38 days), so at least about three weeks of real time, not one sitting.
