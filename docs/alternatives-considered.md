# Alternatives considered

> The reasoning behind the main commitments in `intent.md` and `spec.md`, with the options we did not take. It replaces the stale rationale table in `specification-design.md` (which still lists Vue and Plausible). Revisit a row when its "Revisit when" condition happens, and record the change here in the same PR.

| Decision                | Chosen                                                            | Rejected                                                | Why                                                                                                                                                                                           | Revisit when                                                      |
| ----------------------- | ----------------------------------------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Scheduler (L2, L22)     | SM-2, pure `schedule()`                                           | FSRS now; Leitner boxes                                 | SM-2 is small, well understood and fully unit-tested. FSRS needs parameters and a migration (L22, S11). Leitner is too coarse for ease                                                        | Row 2.13 starts, or SM-2 retention data (M2) looks poor           |
| Storage engine (S1, S3) | `localStorage`, one key per card                                  | IndexedDB; one versioned JSON blob                      | Synchronous, no async code in the grade path, trivially inspectable and exportable. One key per card limits the damage of one bad write. A single blob would rewrite everything on each grade | Quota or performance problems (RK2), or the data exceeds a few MB |
| Pairing (C3, C9)        | Join by `nodeId` plus an English concept slug                     | Direct language-to-language mappings; embeddings        | N languages need N slugs, not N² mappings, and the check is deterministic. Cost: senses that English merges need explicit tags (C13)                                                          | A sixth non-English family makes slugs awkward                    |
| Failed writes (S7, S9)  | Never break the page; tell the learner when progress is not saved | Silent ignore for everything; block the page on failure | A broken page loses a learner on session 1; a silent drop loses their progress. Preferences can fail silently                                                                                 | n/a                                                               |
| Offline (Q7, Q12)       | Runtime-cache service worker, then precache the current level     | Precache the whole site now; no offline                 | Whole-site precache costs bandwidth and Lighthouse budget (audio is 8.5 MB for pt-PT)                                                                                                         | Level precache (Q12) ships                                        |
| Measurement (S6, M1)    | Learner-sent session report                                       | Self-hosted counter (#236); third-party analytics       | Keeps intent P3 true with no request. Cost: only returning learners report (RK3)                                                                                                              | G1 shows the report is too thin to decide on                      |
| Front end               | Astro static pages with vanilla islands                           | React/Vue islands; an SPA                               | No framework runtime to ship, and the Lighthouse budget (Q5) is easy to hold                                                                                                                  | Interactive state outgrows script blocks                          |
| Hosting                 | GitHub Pages                                                      | A backend with accounts                                 | Free, no operations (intent P5, P3). Cost: no cross-device state, no aggregate data (P-6, P-7)                                                                                                | Retention is proven and learners ask for sync                     |
